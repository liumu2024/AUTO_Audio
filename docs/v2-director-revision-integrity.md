# V2 导演修订语义完整性记录

本记录只覆盖 V2 主链路：工作区导演决策、V2 时间线草稿修订、规划结果审查与 Remotion 可见字幕。不会读取或写入 V1 RenderPlan。

## 1. 可见字幕展示约束

- 原因：字幕行数属于渲染层展示规则，不能只停留在规划说明。
- 机制：时间线 overlay 增加 `max_lines`，校验范围为 1–8；Remotion 依据该值裁切显示行数。
- 影响模块：V2 时间线协议、校验器、规划模型 schema、OverlayRenderer。
- 验证：`test:smoke:v2:remotion-timeline-planner`。

## 2. 修订结果与真实草稿对齐

- 原因：聊天回复可能声称方案已修改，但用户后续问答必须以已保存 V2 版本为准。
- 机制：每次执行结果回写时，服务端从 V2 草稿仓库读取当前版本，投影镜头、可见文字、转场、音频和说明为 `timelineFacts`。
- 影响模块：导演工作区会话、V2 草稿仓库、导演提示词与 trace。
- 验证：工作区会话 smoke；真实 Luma 测试中的每轮 `persisted-v2-timeline-facts.json`。

## 3. 方案语义审查

- 原因：结构校验不能发现创作型字幕遗漏、将展示约束写入字幕、或 BGM 修订改写主题等语义问题。
- 机制：规划后的候选方案由独立模型比对本轮请求、基础方案事实与实际差异；失败只允许一次带违规说明的规划纠正，二次失败不保存新版本、不走确定性方案替换。
- 影响模块：`pipeline-v2` 规划服务、修订结果审查器、V2 trace。
- 验证：`test:smoke:v2:timeline-revision-outcome`，以及 Luma 会话 13 次结果审查。

## 4. 导演执行授权与 JSON 一致性

- 原因：讨论性问题曾被提示词误导为修订；另有模型输出同时声明“修订”和 `executionEffect: none` 的矛盾字段。
- 机制：提示词以完整话语意图区分询问/建议与直接方案约束；模型 JSON 内动作字段冲突时，进行一次不改变业务意图的字段一致性修复，失败则安全保留为对话，不由关键词规则推断执行。
- 影响模块：V2 导演模型协议、导演路由、决策 trace。
- 验证：`test:smoke:v2:director-routing`；真实授权探针与 Luma 32 轮质量门禁。

## 5. 字幕重写的变更范围

- 原因：审查器曾把用户授权的“自由重写字幕”错误当成必须保留旧字幕逐字内容。
- 机制：审查器先判断本轮可变更范围；当本轮请求重写可见文案时，旧文案可被替换，但方案的产品主题和未在范围内的镜头/音频事实仍受保护。
- 影响模块：V2 修订结果审查 prompt 与修正指令。
- 验证：`test:smoke:v2:timeline-revision-outcome`；Luma 第 4 轮字幕创作及后续版本。
