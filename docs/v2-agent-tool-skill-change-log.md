# V2 Tool / Skill Registry Change Log

| Point | V2 reason and impact | Mechanism | Modules | Evidence | Remaining item |
| --- | --- | --- | --- | --- | --- |
| Tool/Skill authority | Browser action execution could diverge from persisted V2 drafts | Server Registry validates Tool status, Skill match, authorization and call-id idempotency; Dispatcher writes real V2 state | `agent-tools`, `agent-skills`, director service | `smoke-v2-agent-tool-skill-registry` | Native provider function calling adapter remains deferred |
| Phase loading | Loading every capability would dilute model context | Model receives compact available cards; backend accepts only available, phase-relevant skills | `agent-skills/registry.ts`, router prompt | Registry smoke | Controlled source text is loaded only when a tool needs it |
| Subtitle tracks | One overlay could not express a stable multi-segment subtitle sequence | `caption_tracks` defaults + timed caption overlays + overlap validation + renderer resolution | V2 spec, validator, planner, renderer | Registry smoke validates normal and excessive overlap | Subtitle narration audio alignment is deferred |
| Trace | Tool proposal/actual result were previously indistinguishable | Per-turn request/result trace and real V2 sub-trace linkage | director service, dispatcher | `turn-result.json` and `tool-*.json` on future calls | No provider reasoning summaries are persisted |
| Future interfaces | Audio/RAG/components could be mistaken for available functions | Explicit `planned`/`disabled` tools and typed interfaces, excluded from model catalog | deferred capabilities doc/types | Registry smoke lists available tools only | Provider/persistence implementations deferred |
| Active conversation lifetime | A global `localStorage` pointer reused one Director session across desktop restarts and leaked old draft facts into a new conversation | Active session id is now window-scoped; refresh reuses it, a full desktop restart creates a clean session, and the obsolete global key is removed without deleting V2 drafts | `workspaceSessionLifecycle.ts`, `DirectorChatPanel.tsx` | `smoke-v2-director-session-lifecycle` | Explicit “continue this historical conversation” UI is not implemented |
| Refresh draft restoration | The backend session could retain a V2 draft while the browser timeline Store was empty | A resumed window session reloads its linked draft from the V2 draft repository and opens it in the V2 timeline Store | Director panel, V2 draft API/Store | lifecycle smoke covers the restore callback; frontend build covers the concrete DTO wiring | Historical drafts remain available from the workbench |
| Tool authorization binding | The Director could place authorization evidence at decision level while omitting it from an individual Tool request, causing an authorized create to be rejected | Only evidence grounded in the current user prompt is propagated to each Tool request; stale evidence is discarded | `agent-tools/authorization.ts`, Director service | lifecycle smoke covers valid propagation and stale-evidence rejection | No keyword allow-list is used |
| Trace execution truth | A proposed `timeline.plan` was previously reported as “planner called” even when authorization rejected it | Tool results record whether the planner actually ran; turn trace also records the current raw prompt | Dispatcher, Director service | Type/build validation plus future Director trace | Existing historical traces are intentionally unchanged |
