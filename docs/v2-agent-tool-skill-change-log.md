# V2 Tool / Skill Registry Change Log

| Point | V2 reason and impact | Mechanism | Modules | Evidence | Remaining item |
| --- | --- | --- | --- | --- | --- |
| Tool/Skill authority | Browser action execution could diverge from persisted V2 drafts | The model selects Tools; the server Registry validates Tool status, Skill match, effect/cost permissions and call-id idempotency; Dispatcher writes real V2 state | `agent-tools`, `agent-skills`, director service | `smoke-v2-agent-tool-skill-registry` | Native provider function calling adapter remains deferred |
| Phase loading | Loading every capability would dilute model context | Model receives compact cards; after selection the backend loads the primary `SKILL.md`, package contract and declared read-only dependencies | Skill Registry, manifests, router/planner prompts | Registry smoke verifies content and Remotion dependency loading | None for current available Skills |
| Subtitle tracks | One overlay could not express a stable multi-segment subtitle sequence | `caption_tracks` defaults + timed caption overlays + overlap validation + renderer resolution | V2 spec, validator, planner, renderer | Registry smoke validates normal and excessive overlap | Subtitle narration audio alignment is deferred |
| Trace | Tool proposal/actual result were previously indistinguishable | Per-turn request/result trace and real V2 sub-trace linkage | director service, dispatcher | `turn-result.json` and `tool-*.json` on future calls | No provider reasoning summaries are persisted |
| Future interfaces | Audio/RAG/components could be mistaken for available functions | Explicit `planned`/`disabled` tools and typed interfaces, excluded from model catalog | deferred capabilities doc/types | Registry smoke lists available tools only | Provider/persistence implementations deferred |
| Active conversation lifetime | A global `localStorage` pointer reused one Director session across desktop restarts and leaked old draft facts into a new conversation | Active session id is now window-scoped; refresh reuses it, a full desktop restart creates a clean session, and the obsolete global key is removed without deleting V2 drafts | `workspaceSessionLifecycle.ts`, `DirectorChatPanel.tsx` | `smoke-v2-director-session-lifecycle` | Explicit “continue this historical conversation” UI is not implemented |
| Refresh draft restoration | The backend session could retain a V2 draft while the browser timeline Store was empty | A resumed window session reloads its linked draft from the V2 draft repository and opens it in the V2 timeline Store | Director panel, V2 draft API/Store | lifecycle smoke covers the restore callback; frontend build covers the concrete DTO wiring | Historical drafts remain available from the workbench |
| Tool execution permission | Exact-string authorization matching rejected valid model-selected draft work when the model paraphrased the user | Read/draft Tools no longer require a duplicate textual authorization; delivery Tools retain an explicit execution boundary | Tool Registry, Dispatcher | Registry smoke checks sample/plan/patch versus render | No keyword allow-list is used |
| Creative configuration truth | A stale default `userIntent.aspectRatio=9:16` could contradict an explicit 16:9 UI selection in the model prompt | Defaults remain runtime defaults only; explicit UI controls overwrite the user-intent projection before both frontend submission and server model invocation | Director context builder/store/service | `smoke-v2-director-ui-constraints` | Model-inferred conflicts remain visible for audit but cannot override UI |
| Trace execution truth | A proposed `timeline.plan` was previously reported as “planner called” even when authorization rejected it | Tool results record whether the planner actually ran; turn trace also records the current raw prompt | Dispatcher, Director service | Type/build validation plus future Director trace | Existing historical traces are intentionally unchanged |
| Skill package authority | Local `manifest.ts` files existed but Registry duplicated their metadata and never used them | Each package manifest is now the single source for version, card, Tools, dependencies, prerequisites, facts, output, validation and recovery | Four V2 Skill packages, Skill Registry | Registry smoke reads the packaged instructions and version | Future Skills must use the same package shape |
| Skill/Tool stage binding | A Tool could name a valid Skill that was not selected in top-level `skillRequests` | One resolved execution plan binds every Tool to a selected primary Skill; dependencies cannot authorize Tools | Skill Registry, Tool Registry, Director service | Registry mismatch smoke | None |
| Tool argument contract | Most Tool schemas were generic objects and executors ignored model arguments | Available cards expose concrete schemas; runtime normalization rejects unknown fields and executors consume sample/material/target/draft arguments | Tool Registry and Dispatcher | Registry argument/mode smoke | New Tools must add schema and executor consumption together |
| Result feedback | The pre-Tool model reply remained the final reply even after real execution | Actual results and updated workspace facts go through a second non-executing director-model pass; grounded result fallback is used on provider failure | Director router/service | Tool feedback and full-loop smokes | None |
| Tool exception recovery | A thrown Tool could terminate the SSE before state and trace were saved | Per-Tool exception normalization produces a failed result, recovery advice, idempotency state and trace before the turn closes; rejected Tools never emit a false `tool_started` event | Director service | Full-loop smoke includes an unreadable-sample exception; Registry smoke covers duplicate call IDs | Provider-specific failures remain Tool-level diagnostics |
| Delivery authorization | Exact copied prompt text could reject a valid render decision | Delivery grant derives from one coherent current-turn model decision (`delivery`, `RENDER`, `execute`); read/draft Tools need no duplicate textual grant | Authorization seam, router, dispatcher | Session lifecycle smoke | Final rendering still requires a current V2 draft |
| Workspace read gate | Every workspace-change Tool incorrectly inherited the sample-video requirement | Sample availability is checked only when the selected Tool is `sample.analyze`; `material.inspect` runs independently | Director decision guard | Full Skill/Tool loop smoke | None |
| Persisted draft display | A successful `timeline.plan` wrote the V2 spec to the Store, but the canvas required a transient preview object and the editor remained in sample mode | One V2 draft activation bridge now opens the persisted spec, switches to generation mode and synchronizes playback/task state; canvas and scene cards treat the spec as sufficient and use review data only as optional enrichment | Director panel, V2 canvas/player, editor/playback/task stores | `smoke-v2-director-draft-display` plus live browser create/refresh/click verification | None |
| Reviewable plan facts | The plan canvas exposed only a scene summary, so users could not see the actual captions, timing, animation, visual source or transition they were being asked to revise | A single read-only V2 presentation projection derives scene facts and visible text directly from the persisted spec; the center review and right inspector now show numbered on-screen text segments and map scene/overlay/transition selections to the owning scene | V2 draft workspace projection, generated player, property inspector | `smoke-v2-director-draft-display` asserts overlay text, track defaults, transition facts and selection mapping; frontend build passes | Inline text editing remains a separate interaction; natural-language revision can now refer to the visible numbered segments |
| Historical draft revision binding | A newly created Director session received the historical draft in `context.currentTimeline`, but left the Tool workspace `draftId` and `baseRevision` empty, so `timeline.patch` rejected a visibly open draft | Workspace initialization now promotes the persisted V2 timeline reference, revision and current selection from the request context into the authoritative Tool workspace; later runtime patches keep using the same fields | Director workspace state contract | The captured failing turn carried `v2_draft_6baf7626-4d14-4757-bde5-95446ee469ad` revision 2 while the Tool reported no current draft; `smoke-v2-director-workspace-session` now reproduces and passes this new-session case | None |
| Draft Tool mode resolution | The model could correctly select a draft revision Tool but describe “apply this change” as `execute`; the old mode check rejected the otherwise valid revision | Canonical mode now follows the registered Tool effect: read/draft operations resolve to `preview`, delivery resolves to `execute`; the requested and effective modes are both preserved in SSE and trace | V2 Tool/Skill Registry, Director trace and UI diagnostics | Registry smoke covers an `execute` subtitle revision resolving to `preview` while delivery still rejects `preview` | None |
| Historical creative configuration | Opening a persisted V2 draft restored its timeline but left the creation controls at local defaults, so a later revision could receive a conflicting aspect ratio or duration | One draft activation bridge now restores the supported aspect ratio and duration from the persisted V2 spec before the next Director turn | History dashboard, Director result bridge, creation/editor/playback stores | Draft display smoke first reproduces 16:9/9:16 drift, then verifies 9:16 and six seconds are restored from the draft | Unsupported custom canvas ratios map to the closest supported UI option without rewriting the persisted spec |
| Historical draft summary | History cards used generic branch names and exposed too little information to distinguish drafts | The backend derives a compact title, summary, aspect ratio, duration, scene count and visible-text count from the latest persisted V2 revision; the dashboard shows those facts without loading the full spec into the list response | V2 draft history DTO and dashboard | History UI smoke verifies title, summary, branch label, revision and plan statistics | Arbitrary revision browsing/rollback is not part of the current history index |
| Revision commit gate | The semantic reviewer could approve an unchanged candidate, after which the Dispatcher saved a new revision and claimed the requested subtitle edit was complete | A deterministic final gate compares the scoped, post-filter candidate with the persisted base; zero-diff revisions are rejected before persistence and preserve the current draft | Revision outcome review and Tool Dispatcher | Revision outcome smoke covers a reviewer false-positive and a change outside subtitle scope | The planner may still use one existing semantic correction attempt, but it cannot override the final fact gate |
| Material delivery readiness | Generated-material fallbacks were counted as fulfilled, so one real generated clip plus two blank cards could be reported as a complete three-shot render | Material resolution now exposes planned/resolved/fallback coverage; formal delivery stops before Remotion whenever a planned generated scene is missing, and blank-card previews carry the scene creative intent instead of rendering empty | Material resolver and timeline run service | Material resolver smoke covers blank fallback, missing-scene readiness and complete coverage | An explicit user-approved fallback-delivery policy is not implemented |
| Bounded material execution and progress | Three independent generated shots ran sequentially and the UI stayed at a generic planning state during provider polling | Material jobs use configurable bounded concurrency and emit phase/job progress through Dispatcher SSE; the UI task panel distinguishes draft loading, material generation, standardization and Remotion rendering | Material resolver, run service, Director SSE and task panel | Material resolver smoke verifies three delayed jobs execute concurrently and emit start/completion events | Provider-side rate limits can tune `V2_MATERIAL_GENERATION_CONCURRENCY` |
| Workspace trace session | Director turns, planning, sample analysis and render created unrelated top-level trace directories that were hard to attribute to one conversation | New Director work uses one `sessions/<workspace>/` root, append-only `events.jsonl`, and operation artifact subdirectories; trace context is an execution option and is not persisted in planner state | Trace writer, Director service, sample/planning/render entry points | Trace session smoke verifies two operations share one ordered JSONL stream | Direct standalone V2 HTTP calls retain their task-based trace roots |
| Caption line-limit provenance | A model-selected track default was displayed as “最多两行”, which looked like a hardcoded user requirement | The read-only plan projection records whether the value comes from a track default or a segment override, and the canvas/inspector labels that provenance | V2 draft workspace projection and inspectors | Draft display smoke plus frontend type/build validation | The value remains an editable planning choice, not an inferred user constraint |
| Server-owned Tool identity | The model returned the valid Tool `timeline.plan` with the short label `gen_1`, but a hidden Registry length rule rejected the entire turn | The model label is now optional audit data; the backend derives a canonical call id from workspace, turn request and ordinal for validation, idempotency, SSE and trace | Director protocol, Skill execution plan, Tool Dispatcher | Registry smoke covers short, missing and repeated model labels plus stable replay ids | Provider-native function-call ids can later map into the same audit field |
| Scoped revision transaction | Subtitle candidates were semantically reviewed before the Dispatcher removed out-of-scope fields, so the reviewed candidate could differ from the saved revision | The revision scope is applied once inside the planning module before semantic review, correction and persistence; the final no-diff gate remains authoritative | Timeline revision scope, planning module, Tool Dispatcher | Revision outcome smoke verifies subtitle changes survive while unrelated scene changes are discarded | Additional patch scopes remain planned and must use this same seam |
| Material execution-state ownership | Planner-authored `fulfilled` could skip generation even when no output asset existed, leaving later scenes blank | Unresolved generated jobs are normalized to `planned` at both LLM-plan and execution seams; only a real asset can satisfy fulfillment, and failures remain isolated per scene | LLM planner repair, material resolver, delivery readiness gate | Planner and material resolver smokes cover stale status, three attempted jobs and one isolated provider failure | No silent provider retry is added |
| Trace and progress identity | Timestamp/model-label operation names and coarse progress made local validation delays look like planning or rendering | Turn operations use stable request ids, Tool operations use canonical server ids, render phases append elapsed progress to the session JSONL stream and UI | Director service, trace writer, run service, SSE bridge | Trace/session and material progress smokes; final frontend build | Historical trace directories remain unchanged |
| Creative memory write protocol | The model could claim a preference was persisted without any server-side lifecycle | Director turns may emit `memoryActions` (add/replace/revoke) that cite the current server turn id; the server persists `creative_memories` rows, returns per-action receipts, and the final reply only confirms what actually succeeded | Creative memory module, Director router/service | Creative memory smoke covers receipts, cross-draft rejection, replace inheritance and server-side status downgrades | Provider-native call ids can later map into the same audit field |
| Creative memory status guard | A single inference or a stale cross-project statement could silently become a controlling active preference | Server-side normalization keeps `inferred`, previously revoked, or cross-session repeated preferences at `candidate`; only explicit single-project statements stay `active`; replace inherits the target status/origin | Creative memory service | Creative memory smoke asserts explicit-active, inferred-candidate, near-duplicate-candidate and revoked-readd-candidate | Semantic negation detection and embedding similarity remain deferred |
| Creative memory retrieval and management | Preferences were written but had no user-visible review or recall entry point | Keyword retrieval (BM25 + Chinese bigram + shared-phrase boost) with a per-query audit, `GET /api/creative-memories/search`, and a creative-preferences page that lists, searches, adopts, revokes, edits and deletes memories | Creative memory controller/service, Director service, frontend preferences view | Retrieval smoke (scope/status isolation, top-k, audit reasons) plus frontend build | Vector recall, fusion rerank and conflict resolution are deferred |

| Generic partial revision scopes | `timeline.patch` only accepted a hardcoded `subtitle` scope, so scene/transition, visual-strategy or full-plan edits were impossible without a full replan | The patch Tool now takes `scope: subtitle | scene | visual_strategy | global` (+ `sceneId` for scene/visual_strategy), and a single generic scope seam (`applyV2TimelineRevisionScope` / `evaluateV2TimelineRevisionCommit`) applies the boundary before semantic review and persistence; unknown scopes are rejected instead of passing through | Tool Registry, revision scope seam, outcome review, dispatcher, LLM planner prompt | Registry smoke covers scope/sceneId validation; scoped-edit smoke asserts scene/visual_strategy/global diffs, zero-diff rejection and revision/render binding | `audio` scope canceled; `visual_strategy` field set is the extensible contract for future visual fields |
